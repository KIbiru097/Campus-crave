## 2026-07-21 - Request-Scoped Promise Caching for GraphQL Field Resolvers
**Learning:** In GraphQL APIs backed by relational databases (like PostgreSQL), list queries that expand nested relationships (e.g. `myOrders` expanding `cafe`, `student`, `items`, or `cafes` expanding `average_rating` & `review_count`) trigger severe N+1 database queries when field resolvers independently issue database calls per entity. Instantiating a request-scoped Map in the Apollo context and caching pending/resolved database promises (`getCached(context, key, fetchFn)`) deduplicates concurrent and duplicate queries within a single GraphQL HTTP request tick without requiring external dependencies or global state mutation.
**Action:** Always include a request-scoped cache Map in GraphQL Apollo Server context (`context: async () => ({ cache: new Map() })`) and wrap field resolvers fetching relational entities in a promise-cached wrapper.
