## 2026-07-21 - Request-scoped promise caching for GraphQL N+1 field resolvers
**Learning:** In Apollo Server GraphQL APIs, nested field resolvers (e.g., `Order.cafe`, `Delivery.order`, `AuditLog.user`) trigger separate DB queries per item in list queries (N+1 bottleneck). Creating a request-scoped `Map` in the Apollo `context` (`dataLoaderCache`) allows caching pending/resolved Promises for database queries by key (`type:id`). Returning `await context.dataLoaderCache.get(cacheKey)` ensures error handling inside `async` resolvers catches rejected promises properly, while standardized field selection prevents inconsistent property omissions across queries.
**Action:** Always instantiate a request-scoped Map on Apollo Server context and use `await context.dataLoaderCache.get(...)` with standardized SQL queries for relational field resolvers.
