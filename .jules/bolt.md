## 2026-08-31 - Deduplicating Parallel GraphQL Field Resolvers via Request-Scoped Caching
**Learning:** In GraphQL schemas with nested field resolvers (such as `average_rating` and `review_count` on `Cafe` and `MenuItem`), field resolvers execute concurrently for the same parent entity. Without caching, each field triggers redundant SQL queries against the same underlying table (`reviews`). By attaching a request-scoped `Map` to the GraphQL `context` that stores pending promises per ID, parallel resolvers hit the cache and share a single DB roundtrip per entity.
**Action:** When adding or optimizing GraphQL field resolvers that compute stats or aggregate metrics, always bundle aggregate queries into a single SQL statement (`AVG` + `COUNT`) and cache the lookup promise on the request `context` to prevent N+1 query multiplication.
